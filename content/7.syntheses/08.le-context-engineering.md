## Question du chapitre

Que faut-il donner à voir à un agent, sous quelle forme et à quel moment, pour qu'il fasse le bon travail ? Le chapitre doit expliquer comment se compose le contexte (instructions, skills, outils, mémoire, documentation), ce qu'il coûte, et comment l'entretenir quand les modèles et le code évoluent.

Le corpus compte quatre auteurs : Addy Osmani (trois articles), Thariq Shihipar (deux articles, tous deux sur claude.dev), Birgitta Böckeler (un article) et Jason Gorman (un article).

## Points d'accord

**Trop de contexte nuit.** Birgitta Böckeler ([Context Engineering for Coding Agents](https://martinfowler.com/articles/exploring-gen-ai/context-engineering-coding-agents.html)) écrit que l'efficacité d'un agent baisse quand il reçoit trop de contexte, et conseille de construire les fichiers de règles progressivement. Thariq Shihipar ([The new rules of context engineering](https://claude.dev/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models/)) reconnaît qu'Anthropic contraignait trop Claude Code et recommande un CLAUDE.md léger. Addy Osmani ([Audit your Agent files](https://addyosmani.com/blog/audit-your-agent-files/)) décrit un « cliquet » : chaque erreur ajoute une règle, le fichier s'allonge, les consignes se diluent et sont moins suivies. Jason Gorman ([C.R.E.S.S. Principles for Context Engineering](https://codemanship.wordpress.com/2026/05/04/c-r-e-s-s-principles-for-context-engineering/)) fait de la petite taille (*Small*) et de la spécificité (*Specific*) deux des cinq propriétés d'un contexte efficace : une seule tâche, le minimum d'information nécessaire.

**N'écrire que ce que l'agent ne peut pas déduire.** Addy Osmani ([Stop Using /init for AGENTS.md](https://addyosmani.com/blog/agents-md/)) réserve AGENTS.md aux pièges d'outillage, aux conventions non évidentes et aux zones dangereuses, et exclut ce que l'agent voit en parcourant le dépôt. Thariq Shihipar ([The new rules of context engineering](https://claude.dev/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models/)) demande de ne pas énoncer ce que Claude voit déjà dans le système de fichiers et de consacrer l'essentiel du CLAUDE.md aux pièges du code.

**Charger le contexte au moment où il sert.** Thariq Shihipar ([The new rules of context engineering](https://claude.dev/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models/)) recommande la divulgation progressive : une arborescence de fichiers chargés au bon moment, des procédures déplacées dans des skills. Birgitta Böckeler ([Context Engineering for Coding Agents](https://martinfowler.com/articles/exploring-gen-ai/context-engineering-coding-agents.html)) décrit des « interfaces de contexte » (outils, MCP, skills) que le modèle consulte quand il en a besoin, et des règles limitées à certains chemins de fichiers. Addy Osmani ([Agentic Engine Optimization](https://addyosmani.com/blog/agentic-engine-optimization/)) propose un index `llms.txt` qui renvoie vers les pages, plutôt que de tout fournir d'emblée.

**Les instructions vieillissent avec les modèles.** Birgitta Böckeler ([Context Engineering for Coding Agents](https://martinfowler.com/articles/exploring-gen-ai/context-engineering-coding-agents.html)) note que des instructions nécessaires six mois plus tôt peuvent ne plus l'être. Thariq Shihipar ([The new rules of context engineering](https://claude.dev/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models/)) explique que les modèles récents n'ont plus besoin d'exemples ni de consignes répétées. Addy Osmani ([Audit your Agent files](https://addyosmani.com/blog/audit-your-agent-files/)) en tire un audit régulier : garder une règle, c'est parier que le modèle et le harness n'ont pas progressé depuis qu'elle a été écrite.

**Du vrai code plutôt que des descriptions.** Thariq Shihipar ([The new rules of context engineering](https://claude.dev/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models/)) préfère les références concrètes : une maquette HTML donne de meilleurs résultats qu'une description ou une capture d'écran. Addy Osmani ([Audit your Agent files](https://addyosmani.com/blog/audit-your-agent-files/)) recommande de pointer l'agent vers le code réel plutôt que vers sa description en prose. Jason Gorman ([C.R.E.S.S. Principles for Context Engineering](https://codemanship.wordpress.com/2026/05/04/c-r-e-s-s-principles-for-context-engineering/)) demande un contexte *Current*, le code tel qu'il est plutôt qu'un résumé périmé, et *Empirical*, des faits observés comme le code ou les résultats de tests plutôt que des textes produits par le modèle.

**Les fichiers de contexte générés par le modèle sont suspects.** Addy Osmani ([Stop Using /init for AGENTS.md](https://addyosmani.com/blog/agents-md/)) déconseille les fichiers d'instructions générés automatiquement, et rapporte une étude où ils baissent le taux de succès. Jason Gorman ([C.R.E.S.S. Principles for Context Engineering](https://codemanship.wordpress.com/2026/05/04/c-r-e-s-s-principles-for-context-engineering/)) préfère la réalité observée à l'information produite par le modèle, et déconseille en particulier les fichiers d'architecture ou de standards générés par le modèle.

**Le contexte a un coût.** Birgitta Böckeler ([Context Engineering for Coding Agents](https://martinfowler.com/articles/exploring-gen-ai/context-engineering-coding-agents.html)) rappelle que le contexte supplémentaire coûte de l'argent. Thariq Shihipar ([Prompt caching is everything](https://claude.dev/blog/lessons-from-building-claude-code-prompt-caching-is-everything/)) montre que l'ordre du contexte et sa stabilité déterminent le coût et la latence. Addy Osmani ([Stop Using /init for AGENTS.md](https://addyosmani.com/blog/agents-md/), [Agentic Engine Optimization](https://addyosmani.com/blog/agentic-engine-optimization/)) rapporte des surcoûts mesurés et propose des budgets de tokens par page de documentation.

**Ce qui doit toujours s'appliquer ne peut pas dépendre du modèle.** Birgitta Böckeler ([Context Engineering for Coding Agents](https://martinfowler.com/articles/exploring-gen-ai/context-engineering-coding-agents.html)) distingue le chargement décidé par le modèle, incertain, de celui déclenché par le logiciel de l'agent (les hooks), déterministe. Addy Osmani ([Audit your Agent files](https://addyosmani.com/blog/audit-your-agent-files/)) demande d'inscrire une règle impérative dans un test, un hook ou une permission plutôt qu'en prose. Thariq Shihipar ([The new rules of context engineering](https://claude.dev/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models/)) ne garde des skills très contraignantes que pour les domaines très importants.

## Points de désaccord

### Jusqu'où alléger le contexte : la portée du résultat d'Anthropic

- **Généraliser l'allègement.** Thariq Shihipar ([The new rules of context engineering](https://claude.dev/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models/)) rapporte qu'Anthropic a retiré plus de 80 % du system prompt de Claude Code pour ses modèles récents, sans perte mesurable sur ses évaluations de code. Il en tire une consigne pour le lecteur : simplifier system prompt, skills et CLAUDE.md « comme nous l'avons fait », et laisser le modèle exercer son jugement plutôt que lui donner des règles.
- **Ne pas en faire une cible.** Addy Osmani ([Audit your Agent files](https://addyosmani.com/blog/audit-your-agent-files/)) cite ce résultat, mais précise qu'il n'est pas une cible : les évaluations ne sont pas publiques, et le résultat vaut pour des modèles et un harness précis. Il propose de vérifier par soi-même, par un test sans skills locales, qu'il qualifie de « smoke test » et non de preuve, à répéter quand la décision compte.
- **Une évaluation difficile.** Birgitta Böckeler ([Context Engineering for Coding Agents](https://martinfowler.com/articles/exploring-gen-ai/context-engineering-coding-agents.html)) rappelle qu'il n'existe pas de tests unitaires pour le context engineering : on juge une configuration à l'usage, dans la durée. Elle ajoute que ce n'est pas vraiment de l'ingénierie, puisque l'exécution dépend de l'interprétation du modèle.

**Nature du désaccord :** méthode. Tous vont vers un contexte plus léger ; ils divergent sur ce qu'un résultat obtenu sur des évaluations internes autorise à généraliser. Le contexte compte aussi : Shihipar parle de modèles et d'un harness qu'il connaît de l'intérieur.

**Ce qui permettrait de trancher :** des évaluations publiques et reproductibles, sur plusieurs modèles et plusieurs harness, comparant des configurations de contexte de tailles différentes sur des tâches réelles.

Une différence apparente n'est pas comptée comme désaccord, car elle oppose deux articles du même auteur. Pour un site de documentation, Addy Osmani fait d'AGENTS.md un point d'entrée qui décrit la structure du projet ([Agentic Engine Optimization](https://addyosmani.com/blog/agentic-engine-optimization/)). Pour un dépôt de code, il en exclut les vues d'ensemble et la structure des répertoires ([Stop Using /init for AGENTS.md](https://addyosmani.com/blog/agents-md/)). Les deux usages visent des lecteurs différents.

### Un fichier d'instructions chargé à chaque session, ou un contexte reconstruit à chaque tâche ?

- **Un fichier permanent, court et entretenu.** Addy Osmani ([Stop Using /init for AGENTS.md](https://addyosmani.com/blog/agents-md/)) garde un AGENTS.md réduit aux pièges d'outillage, aux conventions non évidentes et aux zones dangereuses, et l'entretient par un audit régulier ([Audit your Agent files](https://addyosmani.com/blog/audit-your-agent-files/)). Thariq Shihipar ([The new rules of context engineering](https://claude.dev/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models/)) recommande un CLAUDE.md léger, consacré aux pièges du code. Birgitta Böckeler ([Context Engineering for Coding Agents](https://martinfowler.com/articles/exploring-gen-ai/context-engineering-coding-agents.html)) conseille de construire les fichiers de règles progressivement.
- **Un contexte jetable, propre à chaque étape.** D'après l'annotation du chapitre, qui résume les billets de détail de Jason Gorman, ces billets reconstruisent le contexte à chaque étape et déconseillent de charger à chaque tâche des fichiers d'architecture ou de standards ([C.R.E.S.S. Principles for Context Engineering](https://codemanship.wordpress.com/2026/05/04/c-r-e-s-s-principles-for-context-engineering/)). Le billet d'index ne mentionne ni AGENTS.md ni CLAUDE.md.

Le désaccord est partiel. Tous veulent un contexte minimal, et Osmani exclut lui aussi d'AGENTS.md les vues d'ensemble et la structure des répertoires. La divergence porte sur l'existence même d'un socle chargé à chaque session.

**Nature du désaccord :** méthode et contexte. Gorman raisonne tâche par tâche, avec un test d'acceptation pour chaque étape. Osmani, Shihipar et Böckeler décrivent la configuration durable d'un agent sur un dépôt.

**Ce qui permettrait de trancher :** une comparaison, sur les mêmes tâches et le même dépôt, entre un fichier d'instructions permanent et minimal et un contexte reconstruit à chaque tâche, mesurant le taux de réussite et le nombre de passes.

Une autre différence apparente n'est pas comptée comme désaccord. Thariq Shihipar ([The new rules of context engineering](https://claude.dev/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models/)) écrit que les modèles récents n'ont plus besoin d'exemples. Jason Gorman ([C.R.E.S.S. Principles for Context Engineering](https://codemanship.wordpress.com/2026/05/04/c-r-e-s-s-principles-for-context-engineering/)) voit la réussite augmenter avec des exemples BDD dans le prompt. Les deux ne parlent probablement pas du même type d'exemple : chez Gorman, ce sont des critères d'acceptation, qui rendent le contexte *Refutable*, et non des modèles de sortie à imiter. À vérifier à la source de Shihipar avant de conclure.

## État des preuves

**Faits établis.**

- Le prompt caching fonctionne par correspondance de préfixe : tout changement dans le préfixe invalide le cache pour tout ce qui suit. Changer d'outils ou de modèle en cours de session casse donc le cache ([Prompt caching is everything](https://claude.dev/blog/lessons-from-building-claude-code-prompt-caching-is-everything/)). C'est un mécanisme technique documenté par le fournisseur, propre à son API.
- La fenêtre de contexte d'un agent est finie ; une documentation trop longue peut être tronquée ou ignorée ([Agentic Engine Optimization](https://addyosmani.com/blog/agentic-engine-optimization/)).

**Observations empiriques.** La plupart sont rapportées de seconde main par Addy Osmani ; les études elles-mêmes ne sont pas dans le corpus.

- Fichiers AGENTS.md ([Stop Using /init for AGENTS.md](https://addyosmani.com/blog/agents-md/)) : sur 124 pull requests réelles, un AGENTS.md réduit la durée médiane de 28,64 % et les tokens produits de 16,58 % (efficacité seulement, pas la justesse). Une autre étude, sur quatre agents et des benchmarks dont SWE-bench (taille non précisée), trouve que les fichiers générés par un LLM baissent le taux de succès de 2 à 3 % et augmentent le coût de plus de 20 %. Les fichiers écrits par des développeurs l'augmentent d'environ 4 %, pour un coût supérieur de 19 % au plus.
- Audit des fichiers ([Audit your Agent files](https://addyosmani.com/blog/audit-your-agent-files/)) : sur 100 dépôts populaires, 42 % des fichiers présentent un contexte surchargé. Sur 288 exécutions de 17 tâches réelles, les fichiers de contexte n'apportent pas de gain net de justesse, mais changent le comportement des agents. Sur 45 questions de comportement, des résumés en prose répondent à 4, le code source à 27. Une étude sur 206 sessions et 13 développeurs, menée avec un simulateur de développeur à base de LLM, trouve une skill générique plus utile qu'une skill personnelle.
- Anthropic ([The new rules of context engineering](https://claude.dev/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models/)) : plus de 80 % du system prompt retiré sans perte mesurable. Aucun chiffre, nom d'évaluation ni taille d'effet n'est publié.
- Une étude du trafic HTTP de neuf agents de code observe qu'ils compressent une navigation sur plusieurs pages en une ou deux requêtes ([Agentic Engine Optimization](https://addyosmani.com/blog/agentic-engine-optimization/)).
- Deux expériences de Jason Gorman ([C.R.E.S.S. Principles for Context Engineering](https://codemanship.wordpress.com/2026/05/04/c-r-e-s-s-principles-for-context-engineering/)) : la réussite augmente avec des exemples BDD dans le prompt et baisse quand on ajoute de l'information sans rapport. Une seule tâche, 10 essais par variante, sans protocole publié. Le billet d'index invoque plus de trois ans d'expérimentation sans en donner les données.

**Retours d'expérience et opinions.**

- La typologie des mécanismes de contexte et de qui décide de leur chargement ([Context Engineering for Coding Agents](https://martinfowler.com/articles/exploring-gen-ai/context-engineering-coding-agents.html)). L'article ne rapporte aucune mesure ; Claude Code y sert d'exemple principal.
- Les « nouvelles règles » : jugement plutôt que règles, interfaces plutôt qu'exemples, mémoire automatique ([The new rules of context engineering](https://claude.dev/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models/)). Conseils liés à une génération de modèles.
- La conception du harness autour du cache : ordre statique puis dynamique, compaction qui réutilise le préfixe ([Prompt caching is everything](https://claude.dev/blog/lessons-from-building-claude-code-prompt-caching-is-everything/)).
- Les budgets de tokens par type de page et le format `llms.txt` ([Agentic Engine Optimization](https://addyosmani.com/blog/agentic-engine-optimization/)) : heuristiques de l'auteur, non mesurées.
- Partir d'un AGENTS.md presque vide et corriger le code plutôt qu'ajouter une ligne ([Stop Using /init for AGENTS.md](https://addyosmani.com/blog/agents-md/)).
- Les cinq principes C.R.E.S.S. (*Current*, *Refutable*, *Empirical*, *Small*, *Specific*), jugés au nombre de tâches réussies en un minimum de passes ([C.R.E.S.S. Principles for Context Engineering](https://codemanship.wordpress.com/2026/05/04/c-r-e-s-s-principles-for-context-engineering/)). L'auteur les présente comme le fruit de son expérience et invite le lecteur à les tester. Le billet d'index est court ; l'argumentation est dans cinq billets liés.

**Prédictions.**

- Les agents consulteront de plus en plus la documentation, et les premiers à l'adapter en tireront un avantage ([Agentic Engine Optimization](https://addyosmani.com/blog/agentic-engine-optimization/)).
- Les modèles pourraient avoir besoin de moins de contexte à mesure qu'ils progressent ([Stop Using /init for AGENTS.md](https://addyosmani.com/blog/agents-md/)).

## Angles morts

- **La neutralité technologique.** Deux références sur sept viennent d'Anthropic, et Böckeler prend Claude Code comme exemple principal ([Context Engineering for Coding Agents](https://martinfowler.com/articles/exploring-gen-ai/context-engineering-coding-agents.html)). Les principes de Gorman ne dépendent d'aucun outil ([C.R.E.S.S. Principles for Context Engineering](https://codemanship.wordpress.com/2026/05/04/c-r-e-s-s-principles-for-context-engineering/)), mais ne s'appuient pas sur des mesures publiées. Chercher des sources qui décrivent le context engineering avec d'autres agents et d'autres modèles.
- **Les études primaires.** Les mesures sur les fichiers d'instructions passent par les résumés d'Osmani. Chercher les études elles-mêmes, pour en vérifier la méthode et les échantillons.
- **La recherche dans le code.** Le corpus ne traite pas de la façon dont l'agent trouve l'information dans une grande base de code (recherche, indexation, retrieval), alors que Böckeler en fait l'interface de contexte la plus élémentaire ([Context Engineering for Coding Agents](https://martinfowler.com/articles/exploring-gen-ai/context-engineering-coding-agents.html)). Chercher des sources sur le contexte dans les grands dépôts et les monorepos.
- **Évaluer une configuration de contexte.** Böckeler note l'absence de tests unitaires pour le context engineering ([Context Engineering for Coding Agents](https://martinfowler.com/articles/exploring-gen-ai/context-engineering-coding-agents.html)). Gorman propose un critère, le nombre de tâches réussies en un minimum de passes, mais ses essais restent petits et sans protocole publié ([C.R.E.S.S. Principles for Context Engineering](https://codemanship.wordpress.com/2026/05/04/c-r-e-s-s-principles-for-context-engineering/)). Chercher des méthodes pour comparer deux configurations de façon reproductible, en lien avec le [chapitre 13](/partie-4-construire-des-logiciels-fiables/tests-evaluations-et-verification).
- **La sécurité du contexte.** Aucune référence du chapitre ne traite d'un contexte malveillant ou erroné : documentation piégée, serveur MCP compromis, mémoire polluée. Chercher des sources sur ces risques, en lien avec le [chapitre 14](/partie-4-construire-des-logiciels-fiables/code-review-securite-et-livraison).
- **Le contexte partagé en équipe.** Böckeler signale que copier les instructions d'autrui peut surcharger ou contredire une configuration ([Context Engineering for Coding Agents](https://martinfowler.com/articles/exploring-gen-ai/context-engineering-coding-agents.html)), mais aucune référence ne traite de la gouvernance du contexte dans une équipe : qui écrit, qui relit, qui supprime. Chercher des retours d'expérience d'équipes.

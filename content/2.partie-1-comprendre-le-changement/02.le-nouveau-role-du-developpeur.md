- **Central · Addy Osmani** [The New Software Lifecycle](https://addyosmani.com/blog/new-sdlc-vibe-coding/) — Décrit le déplacement des activités dans le cycle de développement.
- **Complémentaire · Addy Osmani** [The Factory Model: How Coding Agents Changed Software Engineering](https://addyosmani.com/blog/factory-model/) — Présente le développeur comme concepteur et exploitant d’un système de production. Renvois utiles : chapitres 16.
- **Complémentaire · Addy Osmani** [The Efficiency Paradox: Why Making Software Easier to Write Means We’ll Write Exponentially More](https://addyosmani.com/blog/the-efficiency-paradox/) — Met en perspective le gain de productivité et l’augmentation des volumes de code.
- **Complémentaire · Addy Osmani** [Is the IDE dead?](https://addyosmani.com/blog/death-of-the-ide/) — Analyse le déplacement du poste de travail de l’éditeur vers l’orchestration. Renvois utiles : chapitres 9.
- **Complémentaire · martinfowler.com** [The role of developer skills in agentic coding](https://martinfowler.com/articles/exploring-gen-ai/13-role-of-developer-skills.html) — Birgitta Böckeler, 25 mars 2025. Même les sessions réussies ont exigé un pilotage constant par le développeur. Classe les erreurs de l’IA selon leur rayon d’impact : délai avant commit, friction dans le flux de l’équipe, maintenabilité à long terme. L’expérience du développeur est ce qui détecte ces erreurs. Renvois : 3, 6, 11. **Limite :** observations sur des outils de 2025.
- **Complémentaire · Pragmatic Engineer** [The impact of AI on software engineers in 2026: key trends. Part 1](https://newsletter.pragmaticengineer.com/p/the-impact-of-ai-on-software-engineers-2026) — Gergely Orosz et Elin Nilsson, 14 avril 2026. Analyse des réponses libres d’une enquête auprès des lecteurs (906 réponses, début 2026, expérience médiane de 11 à 15 ans). Trois profils face aux agents : les *builders*, attachés à la qualité, gagnent en refactoring, migrations et couverture de tests mais relisent davantage de « slop » et vivent une perte d’identité ; les *shippers*, centrés sur le résultat, sont les plus enthousiastes mais accumulent plus vite de la dette ; les *coasters* progressent vite mais produisent beaucoup de code médiocre. Les agents amplifient l’orientation de l’ingénieur au lieu de l’uniformiser. Renvois : 6, 10, 17. **Limite :** échantillon auto-sélectionné, analyse qualitative. **À vérifier :** partie payante non lue.
- **Complémentaire · Simon Willison** [Writing code is cheap now](https://simonwillison.net/guides/agentic-engineering-patterns/code-is-cheap/) — Simon Willison, 23 février 2026. Chapitre du guide *Agentic Engineering Patterns*. Produire du code est devenu presque gratuit, mais produire du bon code reste cher. Les habitudes des équipes ont été bâties sur la rareté du temps de développement (estimations, arbitrages sur l’intérêt d’un test, d’un refactoring ou d’une documentation) et les agents bouleversent ces intuitions. L’auteur définit le bon code : il fonctionne, il est vérifié, il résout le bon problème, gère les erreurs, reste simple, testé, documenté, prêt au changement sans sur-conception, et a les qualités attendues de sa catégorie (sécurité, accessibilité, observabilité). La responsabilité de ce niveau reste au développeur qui dirige les agents. Renvois : 4, 11. **Attention :** guide évolutif, mis à jour sans date de révision affichée ; l’auteur nuance lui-même, en août 2026, le conseil de lancer un agent sur une idée « pas rentable », car l’ajout de fonctionnalités à bas coût érode l’intégrité conceptuelle.

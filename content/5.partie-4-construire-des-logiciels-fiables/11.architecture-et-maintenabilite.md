- **Central · Addy Osmani** [Comprehension Debt - the hidden cost of AI generated code.](https://addyosmani.com/blog/comprehension-debt/) — Présente la dette de compréhension et le risque d’une codebase qui dépasse la maîtrise humaine. Renvois utiles : chapitres 12.
- **Central · Addy Osmani** [Agentic Code Quality](https://addyosmani.com/blog/agentic-code-quality/) — Déplace la qualité vers les contraintes et le système qui entourent la génération. Renvois utiles : chapitres 13,14.
- **Central · Pragmatic Engineer** [The Philosophy of Software Design – with John Ousterhout](https://newsletter.pragmaticengineer.com/p/the-philosophy-of-software-design) — Interview de John Ousterhout par Gergely Orosz, 9 avril 2025. Le design devient plus important à mesure que l’IA écrit le code ; le design est un problème de décomposition. Les agents sont comparés à des « tactical tornadoes » : du code produit vite, qui crée de la dette. Défend les deep modules et les commentaires d’interface. Renvois : 4, 6. **Limite :** interview, pas un texte écrit ; positions de 2025.
- **Central · arXiv** [Echoes of AI: Investigating the Downstream Effects of AI Assistants on Software Maintainability](https://arxiv.org/abs/2507.00788) — Markus Borg, Dave Hewett, Nadim Hagatulah, Noric Couderc, Emma Söderberg, Donald Graham, Uttam Kini et Dave Farley, juillet 2025, révisé en février 2026. Expérience contrôlée et préenregistrée avec 151 participants, à 95 % professionnels : une première vague ajoute une fonctionnalité à une application Java avec ou sans assistant, puis d’autres développeurs font évoluer ces solutions sans IA. L’IA fait gagner du temps en phase 1 (−30,7 % en médiane), mais la phase 2 ne montre pas de différence significative de temps d’évolution ni de qualité du code. Les auteurs ne voient pas de dette au niveau du code, mais signalent deux risques non mesurés : le gonflement des codebases et la « cognitive debt » ; ils recommandent de garder certaines parties sous contrôle cognitif humain. Renvois : 3, 5, 12. Nuance [Assessing internal quality while coding with an agent](https://martinfowler.com/articles/exploring-gen-ai/ccmenu-quality.html). **Limite :** assistants de fin 2024 et non agents, petite application, effets à court terme ; la métrique CodeHealth appartient à CodeScene, qui emploie le premier auteur.
- **Complémentaire · martinfowler.com** [Assessing internal quality while coding with an agent](https://martinfowler.com/articles/exploring-gen-ai/ccmenu-quality.html) — Erik Doernenburg, 27 janvier 2026. Étude de cas sur une application réelle : l’agent livre une fonctionnalité qui marche mais dégrade la qualité interne (types optionnels contournés, cache et complexité inutiles, helpers existants ignorés). Renvois : 3, 14. **Limite :** un seul cas, modèles datés.
- **Complémentaire · martinfowler.com** [The Economic Benefit of Refactoring](https://martinfowler.com/articles/exploring-gen-ai/refactoring-economic-benefit.html) — Giles Edwards-Alexander, 30 juillet 2026. Découper un fichier Rust de 17 155 lignes en modules réduit d’environ 83 % les tokens d’entrée estimés pour une modification type : l’agent trouve plus facilement le plus petit sous-ensemble de code pertinent. Argument chiffré en faveur de la modularité, même quand le code est écrit par des agents. Renvois : 8, 12. **Limite :** une expérience, estimation de tokens.
- **Complémentaire · InfoQ** [The Craft of Software Architecture in the Age of AI Tools](https://www.infoq.com/podcasts/craft-software-architecture/) — Interview de Grady Booch par Shweta Vohra, 11 février 2026. L’architecture est l’ensemble des décisions de conception significatives, la significativité se mesurant au coût du changement ; l’IA ne change pas cette nature. L’agent est un stagiaire enthousiaste mais naïf, à diriger constamment ; Booch vérifie tout ce qu’il produit (« trust but verify ») et la responsabilité revient entièrement à l’humain. Ses inquiétudes : la déqualification, la fin de l’apprentissage des juniors au contact des seniors, et la poussée des LLM vers des designs communs. Renvois : 5, 6, 14. **Contrepoint** à la position de Robert C. Martin (chapitre 14). **Limite :** interview, transcription automatique.
- **Complémentaire · charity.wtf** [AI demands more engineering discipline. Not less](https://charity.wtf/p/ai-demands-more-engineering-discipline) — Charity Majors, 15 juin 2026. Applique au code la leçon de l’immutable infrastructure : quand regénérer devient bon marché, le code devient un cache, une « vue matérialisée de la compréhension », et le vrai produit d’une équipe est sa compréhension partagée. La discipline se déplace vers l’intention et les invariants encodés dans le système, les boucles de feedback courtes, les tests de comportement et de caractérisation, et la production. L’architecture et le comportement deviennent de meilleurs objets de revue que les lignes de code ; l’autrice précise qu’elle ne recommande pas de livrer du code non relu. Renvois : 7, 12, 13, 14. **Attention :** juger la qualité du code généré « réglée » depuis fin 2025 est une opinion de l’autrice ; son rejet des migrations progressives tranche avec [Brownfield Agentic Engineering](https://addyosmani.com/blog/brownfield-agentic-engineering/).
- **Complémentaire · arXiv** [Code for Machines, Not Just Humans: Quantifying AI-Friendliness with Code Health Metrics](https://arxiv.org/abs/2601.02200) — Markus Borg, Nadim Hagatulah, Adam Tornhill et Emma Söderberg (CodeScene et Université de Lund), 5 janvier 2026, accepté à FORGE 2026. Des LLM refactorent des milliers de fichiers Python ; des tests vérifient que le comportement est préservé. Sur le code jugé sain par la métrique CodeHealth, les modèles cassent nettement moins souvent le comportement. Argument empirique pour la thèse : le code lisible pour un humain est aussi celui que l’agent modifie le plus sûrement, et le code dégradé est à la fois celui qui a le plus besoin de refactoring et celui où l’agent est le plus risqué. Renvois : 12, 13. **Limite :** métrique propriétaire évaluée par ses créateurs ; petits fichiers algorithmiques éloignés du code de production ; pouvoir prédictif faible ; écarts non significatifs pour les modèles les plus forts.
- **Complémentaire · CodeScene** [Healthy code needs 22 to 35% fewer tokens for agentic code review](https://codescene.com/blog/does-code-quality-affect-ai-token-costs) — Markus Borg, 26 octobre 2026. Présente une étude préenregistrée de l’Université de Lund (arXiv 2610.21914) : 465 PR écrites par des agents passent dans un pipeline fixe de revue et correction par agents. Une PR sur du code sain coûte 22 à 35 % de tokens en moins qu’une PR sur du code malsain ; le surcoût se concentre dans la revue. Confirme, sur un échantillon plus large, [The Economic Benefit of Refactoring](https://martinfowler.com/articles/exploring-gen-ai/refactoring-economic-benefit.html). Renvois : 8, 14. **Limite :** étude observationnelle, métrique de CodeScene, billet promotionnel. **Attention :** selon le résumé de l’article, l’association disparaît quand on contrôle la taille des fichiers. **À vérifier :** article arXiv lu en résumé.
